# 阶段 8：聊天记录中的博物馆知识库调用核验

更新时间：2026-08-23

## 背景

设备端问答可以通过小智服务端插件 `search_museum_knowledge` 调用 SuperMew 的博物馆检索接口，但原有“聊天记录”页面只展示原始消息，管理端用户难以判断某个问题是否真正经过 RAG。与此同时，“博物馆知识库”页面的问答测试是一次性的前端请求，不会自动写入设备聊天记录。

## 本阶段目标

复用现有的小智聊天记录和工具消息，在聊天记录窗口增加一个轻量的 RAG 状态摘要，帮助演示时快速核验调用链，不新增数据库表、不改变设备协议，也不把密钥或检索原文写入前端代码。

## 实现内容

- 在智能体聊天记录窗口增加“博物馆知识库调用”状态卡片。
- 识别现有 `chat_type=3` 工具消息中的 `search_museum_knowledge` 调用。
- 根据现有工具结果显示四类状态：
  - 已调用并返回检索结果；
  - 已调用但未检索到足够资料；
  - 已调用但请求失败；
  - 已发起调用但聊天记录尚未收到结果。
- 显示当前会话内的调用次数和资料片段数量（按工具结果中的 `[n] 来源` 标记估算）。
- 对于旧会话、关闭聊天记录上报或缺少工具结果的情况，明确提示以小智服务端日志为准。

## 工作原理

```text
设备问题
  -> 小智服务端调用 search_museum_knowledge
  -> SuperMew POST /api/museum/query
  -> 工具结果通过现有 chat_type=3 上报
  -> 智博导览管理平台聊天记录窗口解析并展示 RAG 状态
```

该状态卡片是对已有消息的可视化，不代表新增了一条独立的 RAG 审计记录。真正的调用链故障排查仍以小智服务端的 `trace_id`、SuperMew 请求日志和 HTTP 状态为准。

## 验收步骤

1. 启动 SuperMew、小智服务端、管理端后端和管理端前端。
2. 确认设备使用本地小智服务端，并且设备配置中的 `chat_history_conf` 不为 `0`。
3. 用设备询问“辛追夫人是谁”或其他已上传资料中的问题。
4. 打开“智博导览管理平台 -> 智能体管理 -> 小博 -> 聊天记录”，选择刚刚产生的会话。
5. 在聊天记录顶部确认出现绿色“已调用博物馆知识库”状态；如果资料未召回或请求失败，应显示对应的黄色/红色状态。
6. 同时查看小智服务端日志，核对 `search_museum_knowledge`、`trace_id`、`contexts` 和 `retrieval_empty` 等字段。

## 已知边界

- 本阶段只对已经上报的聊天记录做展示；不会补写历史会话，也不能证明没有上报的旧会话一定未调用 RAG。
- 管理端“博物馆知识库”页面的手工问答仍是独立测试，不会自动出现在设备聊天记录中。
- 当前状态摘要不持久化检索耗时、设备编号、问题文本、来源文档等结构化审计字段。

## 下一阶段建议

阶段 9 再单独设计持久化的 RAG 调用审计表和“博物馆知识库 -> 检索记录”页面，记录 trace ID、设备/会话、问题、检索状态、召回片段、耗时和错误信息，并与现有聊天记录建立关联。
