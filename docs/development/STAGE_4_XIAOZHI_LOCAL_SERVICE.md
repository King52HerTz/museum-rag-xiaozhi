# 阶段 4：本地小智服务端启动回归

更新时间：2026-08-23

## 目标

在阶段 3 已验证 RAG 与小智插件 HTTP 桥接的基础上，启动本地小智服务端，确认管理端配置可以下发、WebSocket 入口可以建立连接，并识别设备端问答前的剩余配置条件。

## 启动条件

本机启动需要满足：

1. SuperMew、manager-api 和管理端 Redis 已运行；
2. 小智服务端 `data/.config.yaml` 已配置 manager-api 地址和密钥；
3. Windows 进程的 PATH 能找到 Opus DLL；本机使用的是被忽略的 `tmp/opus-lib` 解压目录；
4. 由于当前执行环境对 localhost 的 `httpx` 请求会走代理，启动进程需要设置 `NO_PROXY=127.0.0.1,localhost`。这是本机运行环境的绕过项，不是提交到仓库的业务配置。

真实密钥、密码、模型文件和本地配置没有写入本阶段文档或 Git。

## 已验证结果

### 服务端监听

- WebSocket：`ws://127.0.0.1:8011/xiaozhi/v1/`
- HTTP/MCP：`http://127.0.0.1:8013`
- 两个端口均成功监听；WebSocket 使用 `device-id` 和 `client-id` 建立握手成功。
- 当前 HTTP 服务不提供通用 `/health` 路由，访问该路径返回 404 属于现有服务路由设计，不代表端口未启动。

### 管理端动态配置

- 小智服务端可以从 manager-api 获取基础配置；
- `search_museum_knowledge` 已出现在下发的函数列表中；
- 下发配置包含湖南省博物馆、长沙马王堆汉墓陈列和 SuperMew 桥接地址；
- 配置日志中的密钥已由现有日志过滤逻辑脱敏。

### 当前阻塞点

WebSocket 建立后，后台组件初始化失败。证据是小智服务端日志中的模型初始化错误，原因是当前管理端智能体没有配置可用的 LLM API 密钥/模型凭据，导致 LLM 组件未创建，后续无法执行“语音文本 -> 插件 -> LLM 导览话术 -> TTS”。

因此本阶段只能确认：

```text
本地小智服务端启动
    -> 管理端配置下发
    -> WebSocket 握手
    -> 小智知识库插件已注册
```

尚不能宣称设备端完整语音问答已经通过。RAG 上传、检索、聊天和插件直连结果仍以阶段 3 为准。

## 下一步

1. 在智博导览管理平台为演示智能体配置一个可用的 LLM 服务和 API Key，不把密钥提交到仓库；
2. 重启本地小智服务端，确认后台组件初始化不再报错；
3. 用一台设备或 WebSocket 测试客户端发送“辛追夫人为什么能够千年不腐？”；
4. 验收小智日志中的 `search_museum_knowledge` 成功 trace，并确认设备收到导览播报；
5. 如果仍使用官方小智服务，则继续把本地服务端作为可切换的演示/开发环境，不影响现有硬件回退路径。
