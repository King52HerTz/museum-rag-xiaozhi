# 智博导览稳定版产品化开发计划

## 1. 文档目的

本轮开发只完善已经跑通的稳定版系统，把当前“可演示的两个开源项目联调结果”整理成视觉统一、入口清晰、检索可解释的“智博导览管理平台”。

本轮冻结以下工作：

- 不升级 `rag/SuperMew-upstream`；
- 不修改 `yingjian` 下的硬件固件；
- 不迁移小智管理端的 Vue 2 技术栈；
- 不更换向量数据库、检索管线或设备通信协议；
- 不修改现有知识库数据、API Key、密码和运行环境。

稳定版范围：

- 小智管理端：`zhibo-guide-platform/main/manager-web`；
- 稳定版 RAG：`museum-rag`；
- 两个系统之间已经跑通的 manager-api / RAG 桥接链路。

## 2. 当前问题

1. 管理端仍保留“小智”品牌，且蓝紫色风格与 RAG 工作台的米白、金棕色风格不一致。
2. 顶部同时存在普通“知识库”和“博物馆知识库”两个入口，用户无法判断应使用哪一个。
3. 博物馆知识库页面仍使用“演示配置”“演示问题”“接口路径”“trace”等联调用语，检索结果缺少清晰的信息层级。
4. 稳定版 RAG 的系统提示词仍将助手定义为猫咪机器人，可能输出“喵”、猫咪语气或不适合博物馆场景的内容。
5. 过去阶段修改跨度较大，提交不够原子化，不利于回滚和审核。

## 3. 产品定位与设计原则

产品名称统一为“智博导览”。产品面向博物馆运营人员、项目演示人员和知识库维护人员，强调文化感、可信度和清晰的资料溯源。

设计原则：

- 继承稳定版 RAG 工作台的文化型配色，不直接套用通用蓝紫 SaaS 模板；
- 使用语义化设计令牌统一两个独立前端，不强行合并 Vue 2 与 Vue 3 工程；
- 采用 4/8 像素间距体系、统一圆角和阴影层级；
- 不使用 Emoji 作为结构性图标；
- 正文、按钮和状态文字满足可读性要求，保留键盘焦点；
- 加载、空数据、无结果和失败状态都提供下一步操作；
- 高级调试数据默认折叠，普通用户优先看到业务信息。

### 3.1 核心视觉令牌

| 语义 | 颜色 | 用途 |
| --- | --- | --- |
| 主色 | `#B58A4C` | 主按钮、当前导航、重点数字 |
| 主色浅阶 | `#D8B67A` | 悬停、弱强调、装饰线 |
| 页面背景 | `#F8F5EF` | 全局背景 |
| 侧栏背景 | `#F7F0E4` | 导航、辅助区域 |
| 卡片背景 | `#FFFFFF` | 卡片、表格、弹窗 |
| 主文字 | `#5F5546` | 标题、正文 |
| 次文字 | `#817866` | 说明、元信息 |
| 边框 | `#E7DDCD` | 分隔线、输入框 |
| 信息辅助 | `#D9E7F4` | 信息提示、次级标签 |
| 成功 | `#2F855A` | 已完成、服务正常 |

## 4. 信息架构

管理端一级导航调整为：

1. 智能体
2. 知识库
3. 模型配置
4. 设备管理
5. 系统设置
6. 用户菜单

低频管理功能继续保留，但放入“系统设置”下拉菜单。顶部只显示一个“知识库”入口。

旧的 `/knowledge-base-management` 路由暂不删除，访问时重定向到 `/museum-knowledge`，以避免历史书签或旧功能引用产生 404。稳定验证后再评估是否移除旧页面代码。

## 5. 页面改造范围

### 5.1 公共框架与品牌

- 新增“智博导览”原创标志，采用“博物馆檐线 + 对话声波”的抽象图形；
- 提供横版标志、方形图标和单色标志；
- 替换登录页、头部、首页和浏览器标题中的主要“小智”品牌；
- 建立全局设计令牌并覆盖 Element UI 的常用组件状态；
- 统一 Header、页面容器、卡片、按钮、输入框、表格、弹窗、空状态和消息提示。

### 5.2 知识库资料管理

页面采用“概览 + 资料管理 + 检索测试”结构。

资料管理展示：

- 文件名称、格式、所属展览、时代/类别、分块数量、上传时间和处理状态；
- 搜索、筛选、上传、刷新和删除操作；
- 上传、解析、分块、索引和失败状态；
- 明确的空数据、服务离线和失败恢复提示。

第一版只展示现有接口真实返回的数据，不虚构文档状态或统计信息。

### 5.3 检索测试

- 默认只显示问题输入、展览范围和检索按钮；
- `top_k`、trace 等参数放入高级设置；
- 检索结果以有序卡片展示排名、来源、页码、相关度、命中文本和资料标签；
- 原始 trace、RRF、rerank 错误等放入默认关闭的“开发诊断”区域；
- 区分有结果、无相关资料、证据不足、服务异常四种状态；
- 第一版不增加尚无接口支持的完整原文阅读器。

## 6. RAG 提示词规范

系统身份统一为“智博导览——湖南省博物馆数字导览助手”。

必须遵守：

- 文物事实优先依据知识库检索结果；
- 使用检索片段回答时保留 `[1]`、`[2]` 等引用编号；
- 证据不足时只回答有依据的部分，不用模型常识补造尺寸、年代、出土信息；
- 问题指代不清时，请用户补充文物或展览名称；
- 使用自然、专业、亲切的中文，先直接回答，再补充背景；
- 不使用“喵”“主人”“猫咪”“cute cat”、Emoji、颜文字和卖萌语气；
- 不向普通用户暴露内部推理过程、工具链或原始错误堆栈。

## 7. 开发阶段与验收标准

### 阶段 0：稳定基线与开发文档

任务：

- 创建唯一产品化分支 `codex/stable-productization`；
- 记录当前工作区中不属于本轮的修改；
- 固定开发范围和验收清单。

验收：不修改新版 RAG 和硬件目录；不提交环境变量和密钥。

### 阶段 1：设计系统与品牌

任务：

- 新增公共设计令牌和 Element UI 主题覆盖；
- 新增智博导览 SVG 品牌资源；
- 改造登录页、公共头部和首页；
- 替换主要品牌文案和网页标题。

验收：管理端核心页面采用统一的米白金棕视觉；构建通过；核心区域不再显示小智品牌图形。

提交拆分：

- `feat(brand): add Zhibo Guide identity assets`
- `style(ui): add museum design tokens and shared styles`
- `refactor(ui): update login header and home branding`

### 阶段 2：导航与知识库入口

任务：

- 顶部只保留一个“知识库”；
- 旧知识库路由重定向到博物馆知识库；
- 调整导航激活状态与低频菜单。

验收：旧地址可兼容访问；登录和权限不变；顶部没有重复入口。

提交：`refactor(nav): consolidate knowledge base entries`

### 阶段 3：知识库产品化

任务：

- 重构资料概览和文档列表；
- 完善上传、解析、删除、加载、空数据和错误状态；
- 重构检索输入与结果卡片；
- 将原始 trace 移入开发诊断区域。

验收：资料上传、列表刷新、删除和检索功能保持可用；有结果、无结果和失败状态清晰；不再出现演示和接口联调用语。

提交拆分：

- `feat(knowledge): rebuild document management workspace`
- `feat(retrieval): redesign retrieval result presentation`

### 阶段 4：博物馆提示词

任务：

- 替换猫咪机器人系统提示词；
- 更新欢迎语和默认文案；
- 添加身份、证据约束和禁用表达测试。

验收：猫咪相关文本扫描为零；知识库调用和引用规则保留；相关测试通过。

提交拆分：

- `fix(prompt): replace cat persona with museum guide`
- `test(prompt): cover museum tone and evidence rules`

### 阶段 5：全页面一致性与回归

任务：

- 分批统一其余管理页面；
- 检查 1366×768 和 1920×1080；
- 回归登录、智能体、设备、模型、知识库和工作台免登录流程；
- 执行敏感信息和构建检查。

验收：无横向溢出；交互状态清晰；稳定版启动脚本仍可用；设备和 RAG 桥接无回归。

## 8. Git 与安全规范

- 一个逻辑变化一个提交，不把品牌、导航、提示词和接口混在同一提交；
- 每次提交前只暂存本阶段文件，并检查 `git diff --cached`；
- 每个提交都应能够独立构建或通过对应测试；
- 不提交 `.env`、API Key、密码、令牌、上传文档、模型文件和运行日志；
- 不推送到 `icey1287/SuperMew`，根项目只使用用户仓库 `King52HerTz/museum-rag-xiaozhi`；
- 阶段验证通过后再推送，最终统一合并到 `main`；
- 未经确认不删除历史远程分支。

## 9. 完成定义

满足以下条件时，稳定版产品化阶段完成：

1. 管理端和 RAG 工作台具有一致的品牌、颜色和交互语言；
2. 管理端只保留一个可见知识库入口；
3. 知识库页面能够完成真实资料管理和清晰的检索验证；
4. RAG 不再输出猫咪人设内容，且保持基于证据回答；
5. 登录、智能体、设备、RAG 桥接和免登录工作台均通过回归；
6. 所有修改以小而清晰的提交保存，且仓库中不存在敏感信息。
