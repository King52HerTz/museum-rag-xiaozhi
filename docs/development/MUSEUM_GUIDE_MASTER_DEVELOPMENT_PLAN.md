# 智博导览项目总体开发方案

版本：V1.0  
更新时间：2026-09-01  
适用范围：智博导览管理平台、博物馆 RAG 知识库、小智服务端、SmartRing-Plus 导览设备  
当前原则：稳定演示优先、升级隔离验证、资料来源可追溯、密钥不进入 Git

## 1. 文档目的

本方案用于统一项目后续开发方向，解决当前“RAG 稳定版、SuperMew 最新版、小智服务端、管理端和
SmartRing 硬件分别演进，阶段较多且边界容易混乱”的问题。

项目最终不是简单拼接两个开源系统，而是形成以下完整产品闭环：

```text
官方展品资料
    ↓
智博导览展品内容中心
    ├── 生成设备端展品目录、图片和摘要
    ├── 生成可追溯的 RAG 文档并建立索引
    └── 管理成人/儿童导览表达策略
             ↓
SmartRing 展品浏览 → 当前展品上下文 → 小智语音对话 → RAG 检索 → 语音讲解
```

本方案明确：

- 开发顺序；
- 每个阶段的开发范围、产出和验收条件；
- 稳定版与最新版的关系；
- 硬件、管理端、RAG 和资料之间的数据边界；
- 测试、发布、回滚和密钥保护要求。

## 2. 项目总体目标

建设一套面向湖南博物院、以长沙马王堆汉墓陈列为首期内容的智能导览原型，实现：

1. 管理员在智博导览管理端维护展品资料、图片、导览摘要和知识文档；
2. SmartRing 设备启动后选择“成人模式”或“儿童模式”；
3. 设备首页展示智博导览 Logo、欢迎语、“展品浏览”和“开始对话”；
4. 展品浏览页面展示展品名称、图片、短简介和详细介绍；
5. 设备能够从服务端同步已发布展品，并在断网时浏览最近缓存；
6. 用户可从某件展品详情页直接发起语音提问；
7. 小智服务端把当前展品、用户模式和问题传递给 RAG；
8. 成人和儿童得到事实一致、语言风格不同的回答；
9. 管理端能够查看检索证据、来源、调用结果和聊天记录；
10. SuperMew 官方最新版在隔离环境验证通过后，再决定是否替换稳定 RAG 内核。

## 3. 当前基线与边界

### 3.1 已完成能力

当前稳定演示链路已经具备：

- `museum-rag` 支持 docx、PDF、Excel 等资料上传和检索；
- 已提供 `POST /api/museum/query` 博物馆桥接接口；
- 智博导览管理端已经能够上传、查看、删除资料并进行问答测试；
- 小智服务端插件 `search_museum_knowledge` 能够调用 RAG；
- SmartRing 使用官方固件时，已经能够连接本地小智服务端并完成 RAG 语音问答；
- 已有马王堆资料清单、200 条评测用例和 RAG 调用审计能力；
- SuperMew 最新版已经在个人 Fork 的独立升级分支中准备隔离评测。

### 3.2 当前缺失能力

当前还没有：

- 独立的展品结构化数据模型；
- 展品管理页面和发布流程；
- 设备端展品目录、详情和图片同步接口；
- SmartRing 完整小智固件源码上的自定义首页；
- 成人/儿童模式贯穿硬件、服务端、RAG 和 TTS 的会话字段；
- “浏览当前展品后继续追问”的展品上下文；
- 自定义硬件固件的独立 OTA 发布链路。

### 3.3 三条代码线的职责

| 代码线 | 职责 | 当前处理原则 |
| --- | --- | --- |
| 根项目 `museum-rag-xiaozhi` | 小智服务端、管理端和稳定 RAG 集成 | 作为当前演示主线 |
| `King52HerTz/SuperMew-museum` | 基于 SuperMew 官方最新版的升级验证 | 只在隔离环境验证，不直接覆盖稳定版 |
| 待建立的智博导览固件仓库 | SmartRing 自定义小智固件 | 独立仓库和独立 OTA，不与服务端代码混放 |

`icey1287/SuperMew` 和 `78/xiaozhi-esp32` 均只作为上游代码来源。默认不向原作者仓库推送。

## 4. 核心架构方案

### 4.1 稳定版与最新版双轨运行

当前产品开发继续使用已经跑通的 `museum-rag`，先完成硬件、展品管理和分众导览闭环。

SuperMew 最新版继续独立执行：

```text
隔离数据库 → 隔离对象存储 → 隔离向量库 → 官方资料重新上传 → 200 条真实 RAG 评测
```

只有满足以下条件才考虑切换：

- 最新版可以稳定启动；
- 数据库迁移完整；
- 资料全部重新索引；
- `/api/museum/query` 兼容接口通过；
- 小智硬件端到端回归通过；
- 检索质量不低于稳定版；
- 有明确回滚版本。

因此，最新版升级不阻塞硬件主线开发。

### 4.2 展品主数据是一切内容的唯一来源

不能让硬件直接解析 RAG 文档，也不能分别维护“设备资料”和“知识库资料”。应增加展品内容中心：

```text
展品主数据
    ├── 设备用：名称、封面、成人摘要、儿童摘要、排序、版本
    ├── RAG 用：完整事实、别名、年代、尺寸、工艺、来源、展品编号
    └── 管理用：审核状态、发布时间、来源记录、修改历史
```

发布一件展品时，同时完成：

1. 生成设备端目录和详情数据；
2. 生成或更新该展品的 RAG Markdown 文档；
3. 触发异步索引；
4. 索引成功后将展品标记为可对话；
5. 更新设备内容版本号。

### 4.3 分众导览不拆分事实知识库

成人和儿童使用同一套官方事实和检索结果，只改变表达策略。

提示词组合顺序：

```text
事实与安全规则
  + 智博导览员基础角色
  + 成人/儿童表达策略
  + 当前展品上下文
  + RAG 检索证据
  + 当前会话历史
```

这样可以避免两套知识库内容不一致，也便于统一评测事实正确性。

### 4.4 设备目录同步与语音对话分离

- 展品目录、图片和摘要：使用 REST 接口和本地缓存；
- 实时语音：继续使用小智 WebSocket；
- RAG：仍由小智服务端插件调用；
- 固件 OTA：使用独立固件版本和发布通道。

展品内容变化频率较低，不需要通过 WebSocket 实时推送。设备启动或进入展品页时检查版本即可。

## 5. 目标功能设计

### 5.1 智博导览管理端

新增“展品管理”，至少支持：

- 展品列表、搜索、草稿、发布和下线；
- 名称、别名、展览、年代、材质、尺寸、出土地点；
- 封面图和设备端缩略图；
- 完整介绍、成人摘要、儿童摘要；
- 来源网址、来源类型、采集日期和版权说明；
- 关联 RAG 文档和索引状态；
- 内容版本号和发布时间；
- 排序和推荐标记；
- 预览成人模式、儿童模式和设备端效果。

新增“导览策略”，至少支持：

- 基础导览员提示词；
- 成人表达策略；
- 儿童表达策略；
- 策略版本、启用状态和修改记录；
- 同一问题的双模式对比测试。

### 5.2 SmartRing 设备

设备页面状态建议为：

```text
启动页
  ↓
成人/儿童模式选择
  ↓
智博导览首页
  ├── 展品浏览
  │     ├── 展品卡片
  │     ├── 展品详情
  │     ├── 语音讲解
  │     └── 问小智
  └── 开始对话
        └── 保留当前 GIF、字幕和语音交互界面
```

圆形 360×360 屏幕的设计约束：

- 主要按钮放在圆形中心安全区，避免边缘误触；
- 一屏展示一件展品，不复制手机端长列表；
- 详情以 80～150 字短文为主；
- 长内容通过语音讲解和继续提问获取；
- 图片使用设备专用 JPEG 缩略图；
- 显示下载状态、离线状态和更新时间；
- 长时间无人操作后回到模式选择页，避免公共设备继承上一位游客的模式和会话。

### 5.3 成人与儿童导览策略

| 项目 | 成人模式 | 儿童模式 |
| --- | --- | --- |
| 语气 | 专业、自然、沉稳 | 亲切、活泼、温和 |
| 内容 | 年代、工艺、背景和价值 | 外观、用途、趣味知识和生活类比 |
| 句式 | 信息完整，可适当使用术语 | 短句，首次出现术语时解释 |
| 长度 | 适合 40～90 秒朗读 | 适合 20～45 秒朗读 |
| 互动 | 补充背景和关联展品 | 猜一猜、找一找、简单观察题 |
| TTS | 平稳语速 | 稍慢语速、停顿更清晰 |

儿童模式必须遵守：

- 不编造故事；
- 类比不能改变事实；
- 墓葬、遗体等内容使用温和、科学的表达；
- 一次重点不超过 2～3 个；
- 不采集儿童姓名、年龄等不必要的个人信息。

### 5.4 RAG 检索与当前展品上下文

每次导览问题至少携带：

```json
{
  "audience_mode": "adult | child",
  "exhibit_id": "当前展品编号或空",
  "museum": "湖南博物院",
  "exhibition": "长沙马王堆汉墓陈列",
  "question": "用户问题"
}
```

检索规则：

1. 有 `exhibit_id` 时，优先检索当前展品；
2. 当前展品证据不足时，再扩展到同一展览；
3. 没有当前展品时，按普通博物馆问答检索；
4. 检索失败不能静默退化为无依据 LLM 回答；
5. 管理端必须能看到命中文档、片段和调用结果。

## 6. 建议数据模型

本节是接口和数据库设计依据，不代表当前已经实现。

### 6.1 展品 Exhibit

核心字段建议包括：

- `id`：内部主键；
- `exhibit_code`：稳定展品编号；
- `name`、`aliases`；
- `museum`、`exhibition`；
- `era`、`material`、`dimensions`、`excavation_location`；
- `cover_image`、`device_thumbnail`；
- `full_description`；
- `adult_summary`、`child_summary`；
- `source_type`、`source_url`、`collected_at`、`copyright_note`；
- `rag_document_id`、`rag_index_status`；
- `status`、`sort_order`、`content_version`；
- 创建、修改、发布人员和时间。

### 6.2 导览策略 AudienceProfile

- `mode`：`adult` 或 `child`；
- `display_name`；
- `prompt_template`；
- `max_answer_length`；
- `tts_voice`、`tts_speed`；
- `enabled`、`version`；
- 修改人和修改时间。

### 6.3 设备内容清单 DeviceManifest

- 内容版本号；
- 发布时间；
- 展品编号列表；
- 每件展品数据版本；
- 图片 URL、大小和校验值；
- 是否强制刷新；
- 最低兼容固件版本。

### 6.4 会话上下文 GuideSession

- 设备编号；
- 智能体编号；
- 成人/儿童模式；
- 当前展品编号；
- 会话开始和最后活动时间；
- 提示词版本；
- RAG 索引版本。

会话记录可以保存模式和展品编号，但不采集不必要的游客身份信息。

## 7. 接口边界建议

正式开发前先冻结接口契约，再分别开发管理端、服务端和固件。

### 7.1 管理端接口

建议提供：

```text
GET    /museum/exhibits
POST   /museum/exhibits
PUT    /museum/exhibits/{id}
POST   /museum/exhibits/{id}/publish
POST   /museum/exhibits/{id}/unpublish
GET    /museum/exhibits/{id}/rag-status
GET    /museum/audience-profiles
PUT    /museum/audience-profiles/{mode}
POST   /museum/audience-profiles/compare
```

这些接口必须使用管理端登录权限。

### 7.2 设备内容接口

建议提供：

```text
GET /api/guide/manifest
GET /api/guide/exhibits
GET /api/guide/exhibits/{exhibit_code}
GET /api/guide/assets/{asset_id}
```

设备只获取已发布内容。图片 URL 应支持校验和缓存，设备不能使用管理端账号密码。

### 7.3 对话上下文

成人/儿童模式和当前展品可以在设备连接信息、会话配置或专用上下文消息中传递。最终方式需要以
官方 `xiaozhi-esp32` 当前协议能力为准，不能在未验证协议前自行修改 WebSocket 数据格式。

## 8. 详细开发阶段与顺序

## 阶段 0：冻结稳定基线

目标：确保后续任何硬件或升级失败都不会影响当前可演示系统。

开发计划：

- 记录稳定版 Git commit、依赖版本和本地端口；
- 验证管理端登录、资料上传、检索测试、智能体、设备和语音问答；
- 保存数据库、上传目录和本地配置的恢复说明；
- 记录一个成人模式基准问题集；
- 为当前演示版建立稳定标签。

产出：

- 稳定基线清单；
- 一键启动说明；
- 回滚说明；
- 当前演示录像或截图。

验收标准：

- 设备能回答马王堆问题；
- 管理端能看到 RAG 来源；
- 重启后数据和账号仍存在；
- 未提交任何真实密钥。

回滚：始终回到此稳定标签和原有数据卷。

## 阶段 1：固件源码基线与仓库隔离

目标：先用源码复现截图一的现有语音能力，确认具备继续改界面的基础。

开发计划：

- 在用户个人 GitHub 下 Fork 官方 `78/xiaozhi-esp32`；
- 新建独立固件仓库或保留独立 Fork，不放入当前服务端仓库；
- 建立唯一板型 `viewe-smartring-plus-museum`；
- 根据 SmartRing-Plus A/B 实物版本配置屏幕、触摸、音频和电源；
- 编译、烧录并验证 Wi-Fi 配网、OTA、麦克风、扬声器、触摸、GIF 和字幕；
- 连接当前本地小智服务端，验证 RAG 问答与官方固件一致；
- 保存可恢复的原官方固件和自定义基线固件。

产出：

- 可编译的智博导览板级固件；
- 独立板型和固件版本号；
- USB 恢复固件；
- 烧录与串口诊断说明。

验收标准：

- 连续多轮语音对话正常；
- 触摸、显示和音频没有明显异常；
- RAG 调用结果与当前稳定固件一致；
- 自定义板型不会被官方普通 OTA 覆盖。

阻断条件：如果无法用源码复现当前语音固件，停止界面开发，先解决板级适配，不同时开发后台同步。

## 阶段 2：设备静态 MVP 与分众模式

目标：不依赖后台新增接口，先验证圆屏交互设计和页面状态切换。

开发计划：

- 制作智博导览 Logo 和欢迎页；
- 实现成人/儿童两个大按钮；
- 实现“展品浏览”和“开始对话”首页；
- 内置 1～3 件静态展品数据和压缩图片；
- 实现展品卡片、详情、返回和左右切换；
- 点击“开始对话”进入现有 GIF 对话页面；
- 点击“问小智”进入对话并在设备本地记录当前展品；
- 长时间无操作后回到模式选择页。

产出：

- 可演示的设备静态交互原型；
- 圆屏页面规范；
- 图片尺寸和内存测试结果。

验收标准：

- 所有按钮在真机可稳定点击；
- 页面切换无明显卡顿或内存泄漏；
- 对话结束可以返回首页；
- 成人/儿童切换不会继承上一模式会话。

回滚：烧录阶段 1 的固件基线。

## 阶段 3：展品内容中心和管理页面

目标：建立设备展示和 RAG 共用的结构化展品主数据。

开发计划：

- 设计并评审 Exhibit、来源和发布状态数据模型；
- 实现展品增删改查；
- 实现图片上传、缩略图生成和预览；
- 实现成人摘要和儿童摘要；
- 实现草稿、发布和下线；
- 展示 RAG 文档和索引状态；
- 实现操作权限和修改记录；
- 首批录入 10 件马王堆重点文物。

产出：

- 展品管理前后端；
- 数据库迁移文件；
- 图片存储规则；
- 10 件首批展品主数据。

验收标准：

- 管理端能完整维护一件展品；
- 未发布内容不会出现在设备接口；
- 图片能够生成适合 360×360 屏幕的缩略图；
- 来源、采集时间和版权备注不能为空；
- 数据库升级和回滚脚本可验证。

## 阶段 4：设备目录同步与离线缓存

目标：管理端发布展品后，设备无需重新刷固件即可获取更新。

开发计划：

- 实现 manifest、列表、详情和图片接口；
- 设计内容版本、图片校验值和最低兼容固件版本；
- 设备启动后检查 manifest；
- 只下载发生变化的展品和图片；
- 优先使用 TF 卡，必要时使用 Flash 文件系统；
- 下载失败保留上一版完整内容；
- 展示同步、离线、更新失败状态；
- 增加设备访问凭据，不在固件中放管理端密码或 RAG API Key。

产出：

- 设备内容发布接口；
- 固件同步和缓存模块；
- 内容版本与缓存清理规则。

验收标准：

- 管理端修改并发布后，设备能够看到新版本；
- 未修改图片不会重复下载；
- 断网重启仍能浏览最近成功版本；
- 下载中断不会破坏原缓存；
- 非法设备不能获取管理接口数据。

## 阶段 5：官方资料整理与双用途发布

目标：建立足量、官方、可追溯且适合设备与 RAG 的马王堆资料库。

资料优先级：

1. 湖南博物院官方网站和藏品数据库；
2. 湖南博物院微信小程序中公开展示的资料；
3. 湖南博物院出版物、展览资料和公开研究文章；
4. 其他权威博物馆或学术来源，仅作为补充并单独标注。

开发计划：

- 制定 Markdown 和图片文件夹模板；
- 先人工整理小程序资料，不把小程序自动爬取作为主线阻断项；
- 对名称、尺寸、年代、出土地点等字段交叉核验；
- 每件展品保存来源和采集日期；
- 从展品主数据生成 RAG Markdown；
- 上传后检查分块和检索证据；
- 完成 10 件核心文物后扩展到 30～50 件；
- 建立资料更新和下线机制。

建议首批：

- 素纱单衣；
- T 形帛画；
- 黑地彩绘棺；
- 红地彩绘棺；
- 云纹漆案；
- 辛追墓出土竹简；
- 印花敷彩纱丝绵袍；
- 绢地“长寿绣”；
- 漆器和遣策代表文物；
- 马王堆一号墓与辛追夫人相关基础资料。

验收标准：

- 每件展品至少有一个官方来源；
- 关键数值能够回溯到来源；
- 设备摘要与 RAG 完整文档事实一致；
- 图片有来源和使用说明；
- 不把原始资料、版权受限大图或小程序缓存直接提交到 GitHub。

## 阶段 6：成人/儿童提示词和语音策略

目标：让两种模式共享事实，但形成稳定、可评测的表达差异。

开发计划：

- 把基础角色、事实规则和受众策略分层；
- 在管理端维护成人、儿童策略版本；
- 增加同题双模式对比测试；
- 将 `audience_mode` 传到小智服务端和 RAG 桥接；
- 根据模式控制回答长度、句式和互动方式；
- 根据可用模型配置不同 TTS 音色或语速；
- 聊天记录保存模式和提示词版本；
- 切换模式时创建新会话。

验收标准：

- 同一问题的关键事实一致；
- 儿童模式句子更短、术语有解释；
- 儿童模式不会虚构故事；
- 墓葬和遗体内容表达温和、科学；
- 成人模式保留必要的历史和工艺信息；
- 模式和提示词版本可在审计记录中确认。

## 阶段 7：当前展品感知的 RAG 对话

目标：实现“正在浏览哪件文物，就优先回答哪件文物”的导览体验。

开发计划：

- 确认官方小智协议中传递会话上下文的安全方式；
- 将 `exhibit_id` 与设备会话绑定；
- 扩展博物馆桥接请求上下文；
- 检索时优先过滤当前展品，再扩展到当前展览；
- 在 RAG 证据不足时明确说明；
- 展品详情页增加“问小智”和“语音讲解”；
- 管理端聊天记录显示当前展品和模式；
- 验证退出展品后上下文被正确清除。

验收标准：

- 浏览素纱单衣后问“它为什么这么轻”能命中素纱单衣资料；
- 切换到黑地彩绘棺后，不继续引用上一件文物；
- 没有当前展品时仍能进行普通博物馆问答；
- 每次回答都能追踪到实际检索证据；
- RAG 不可用时有清晰提示，不伪装成知识库回答。

## 阶段 8：端到端测试与现场稳定性

目标：验证真实博物馆式使用过程，而不仅是单个接口可用。

测试范围：

- 成人/儿童模式切换；
- 设备首次同步、增量同步和断网缓存；
- 展品浏览、详情、语音讲解和继续追问；
- 普通问题、展品问题、跨展品问题和无答案问题；
- RAG 服务停止、模型限流、图片下载失败和局域网中断；
- 长时间连续运行、重复进入退出对话、内存和温度；
- 管理端登录、权限、发布、索引状态和审计；
- 密钥扫描和 Git 提交检查。

质量指标建议：

- 200 条马王堆评测集通过既定门禁；
- 核心 10 件展品人工问题全部有正确来源；
- 设备连续运行 2 小时无重启和明显内存下降；
- 内容更新失败时可继续使用旧版本；
- 成人/儿童回答关键事实一致；
- 现场演示链路具备一键恢复方案。

产出：

- 测试报告；
- 缺陷清单和关闭记录；
- 答辩演示脚本；
- 故障回退手册。

## 阶段 9：SuperMew 最新版真实评测与迁移决策

目标：在产品闭环稳定后，判断新版 RAG 内核是否值得替换。

开发计划：

- 完成隔离 Linux/WSL 环境启动；
- 使用独立 PostgreSQL、Redis、Milvus、MinIO 和上传目录；
- 将同一批官方资料重新上传和索引；
- 执行 200 条 live RAG 评测；
- 与稳定版比较准确率、证据、时延、资源占用和运维复杂度；
- 执行小智桥接和硬件回归；
- 形成“升级、暂缓或只迁移部分能力”的决策报告。

验收标准：

- 报告明确使用真实隔离索引；
- 新版质量不低于稳定版；
- `/api/museum/query` 契约兼容；
- Windows 主机可以通过 WSL 或明确部署方式稳定运行；
- 数据重建和回滚路径可执行。

不通过时：继续使用稳定 RAG，不影响前面已经完成的硬件和管理端功能。

## 11. Git 与仓库管理方案

为避免分支继续膨胀，后续不再为每个阶段保留长期分支。

服务端主仓库建议只保留：

- `main`：稳定演示版本；
- 一个当前集成分支；
- 每个功能使用短期 `feature/*`，合并后删除。

SuperMew Fork 建议保留：

- 官方同步基线；
- `museum-upgrade` 升级验证分支。

硬件固件独立仓库建议保留：

- `main`：可烧录稳定固件；
- `develop`：当前硬件开发；
- 短期功能分支合并后删除。

每次提交必须满足：

- 不包含 `.env`、API Key、密码和设备私有令牌；
- 不包含模型、数据库卷、构建产物和用户上传资料；
- 不包含小程序缓存和版权受限原图；
- 提交信息标明影响范围：`server`、`rag`、`manager`、`firmware` 或 `docs`；
- 每个里程碑通过后再合并，失败分支不进入 `main`。

## 12. 安全和隐私要求

- API Key 只保存在本地私有配置或服务端密钥管理中；
- 设备不保存管理端账号、RAG Key 或模型 Key；
- 设备使用独立设备凭据访问公开后的展品内容；
- 图片下载接口限制访问范围并防止目录遍历；
- 管理端修改提示词和发布内容需要权限与审计；
- 聊天记录不保存儿童姓名、联系方式或精确身份；
- 日志不得打印密钥、密码、完整 Token；
- GitHub 推送前执行密钥和大文件检查。

## 13. 主要风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 无法从源码复现当前官方固件 | 首页和浏览功能无法安全集成 | 阶段 1 先验证，未通过不继续做动态后台 |
| SmartRing A/B 屏幕版本不一致 | 花屏、触摸错位 | 烧录前确认实物型号并分别保存配置 |
| 自定义固件被官方 OTA 覆盖 | 功能丢失甚至无法启动 | 使用唯一板型和自有 OTA 通道 |
| 圆屏内存和存储不足 | 图片卡顿、重启 | 缩略图、分批缓存、TF 卡、下载校验 |
| RAG 文档与设备摘要不一致 | 用户看到和听到的内容冲突 | 使用同一展品主数据生成两路内容 |
| 儿童模式出现编造故事 | 事实错误和教育风险 | 共享检索证据、固定规则、双模式评测 |
| 小程序无法稳定抓取 | 资料建设受阻 | 首期人工整理，官网优先，小程序补充 |
| 最新 SuperMew Windows 不兼容 | 升级无法直接运行 | 隔离 WSL/Linux 验证，不替换稳定版 |
| 分支过多 | 无法判断哪个版本可用 | 两个长期分支以内，功能分支合并即删 |
| 本地网络变化 | 设备连接失败 | 管理端配置局域网地址并准备现场网络方案 |

## 14. V1.0 完成定义

只有同时满足以下条件，项目才算完成第一版：

- SmartRing 有智博导览 Logo、模式选择、首页、展品浏览和原有语音对话；
- 至少 10 件马王堆重点文物可在管理端维护并同步到设备；
- 每件展品都有官方来源、封面、成人摘要、儿童摘要和 RAG 文档；
- 浏览某件展品后可以围绕该展品追问；
- 成人和儿童模式事实一致、话术明显不同；
- 管理端能够核验 RAG 证据和聊天上下文；
- 设备断网时可以浏览缓存，联网后可以继续对话；
- 一键启动、固件恢复、数据库回滚和密钥保护均有文档；
- 稳定版可以随时恢复；
- 是否升级 SuperMew 最新版有独立评测结论，而不是凭“代码更新”直接替换。

## 15. 下一步

按本方案开始开发时，首先执行阶段 0 和阶段 1：

1. 冻结并复核当前稳定演示基线；
2. 确认 SmartRing-Plus 是 A 版还是 B 版；
3. 获取或 Fork 完整 `xiaozhi-esp32` 固件源码；
4. 建立唯一智博导览板型；
5. 在不加新页面的情况下，先从源码复现当前 GIF、语音和 RAG 对话。

阶段 1 通过后，才进入首页、模式选择和展品浏览开发。
